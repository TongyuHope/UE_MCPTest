# TerraceTools 梯田制作工具规划

日期：2026-10-20。目标引擎：本机 UE 5.8.3。插件：`Plugins/TerraceTools`。

最后更新：2026-10-21。M2 首版源码（0.3.0）已编写，范围为田埂、土质护坡、材质、碰撞与更新清理，待用户编译/验收；台阶、垂直石墙、共享边和 Static Mesh 烘焙仍未实现。见 [M2 使用与验收](M2田埂与护坡.zh-CN.md)。

0.3.1 修复补充：用户反馈边界支撑高度检查失败。地形后端新增按地形/遮罩精度计算的自动平坦支撑余量，护坡范围和冲突预检同步扩大，报错提供实际/目标高度。修复待用户编译/验证，不代表 M2 已验收。

0.4.0 方向调整：用户反馈可生成田埂护坡，决定先采用 Landscape 台地 + 自建 PCG 图沿线摆放田埂，之后尝试地形土埂。插件提供带标签、田面标高且绕序统一的 PCGBundSpline，以及 PCGData 和明确同步入口；旧过程网格保留为实验选项。详见 [PCG 接入说明](PCG田埂接入.zh-CN.md)。本轮不编译或运行 UE，按用户要求先提交 Git。

当前进度：M0（0.1.0）与 M1（0.2.0）均已获用户反馈“当前检验通过”，未单独提供逐项测试记录。具体操作与首版限制见 [M1 地形整平](M1地形整平.zh-CN.md)。M1 当前仅提交 Patch 更新，不宣称碰撞同步完成，尚未接入下游 PCG。用户补充的 LandscapeExtra 文章已阅读，后续设计见 [参考文章与方案调整](参考文章与方案调整.zh-CN.md)。

## 1. 目标与已确定的方案

地编在编辑器中绘制和调整梯田，玩家能够进入田块、沿田埂行走。采用 **Landscape 局部整平 + 网格田埂及挡土结构 + PCG 作物** 的混合方案，以编辑器制作为主，游戏运行时使用保存后的结果。

同一份田块数据驱动地形、结构和种植点。PCG 负责组织、分布和实例化；地形写入、几何拓扑和编辑事务由配套 C++ 编辑器工具负责。首版不要求运行时改地形，不修改引擎源码，不改写项目已有 PCG Biome 插件。

纯网格也可以提供可行走碰撞；选择混合方案是为了维护大面积山体连接与地面碰撞，并非引擎限制。

## 2. 组成与坐标约定

- 田面：Landscape 整平台地，水田保持水平，首版统一水平。
- 田埂：高于田面的窄带，与上下级之间的挡土侧壁分开参数化。
- 挡土结构：从上级田边连接到下级田面或外围地形，支持土坡与墙体预设。
- 作物：按行列布局，裁剪到田块内部，留出田埂、沟渠和通行区域。
- 后续设施：台阶、道路、进出水口、排水沟、独立水面。

长度单位均为厘米。边界在世界 XY 平面上处理，田面高度为 `Actor 世界 Z + ElevationOffset`。首版支持平移、绕 Z 旋转和正向 XY 缩放；拒绝倾斜、负缩放和非有限输入。边界样条控制点的 Z 不驱动田面起伏；编辑操作可将其统一到局部 Z=0。作物朝向使用世界 XY 方位角。

## 3. 地编工作流

1. 放置 Terrace Group，选择目标 Landscape。
2. 从梯田组创建 Plot，编辑闭合样条及标高。
3. 校验边界和组内关系；先查看目标标高线，再决定是否写入地形。
4. 更新地形与结构，等待高度、碰撞等相关数据完成更新。
5. 更新作物；只改作物参数时跳过地形重建。
6. 保存关卡，定稿时烘焙需要的网格资产和生成结果。

预览不提供行走表面，也不会自动修改 Landscape。实际地形更新必须由明确的命令触发；拖动控制点期间不持续写入地形。

## 4. 插件架构

保留空白插件的 `TerraceTools` 模块名作为 Runtime 模块，新增 `TerraceToolsEditor`。避免为尚无现有资产的模块改名引入不必要的迁移。

| 层 | 职责 | 边界 |
| --- | --- | --- |
| TerraceTools / Runtime | Actor、田块参数、稳定 ID、边界快照、二维几何计算 | 不依赖 UnrealEd；无 Tick 生成 |
| TerraceToolsEditor / Editor | 详情面板、视口标高预览、事务、校验、地形与网格生成、烘焙 | 不进入 Shipping |
| Content | 通用 PCG 图、材质、基础断面、预设 | 项目专用资产通过配置引用 |

优先使用现有引擎能力，按里程碑引入 LandscapePatch、Geometry Script 和 PCG 依赖。M0 不先引入未使用的依赖。

Runtime 名称不代表游戏中重新生成。只要关卡还引用插件 Actor/组件就需要对应模块；完全脱离工具要转换为普通引擎对象并清除插件类型引用，单纯烘焙网格不能保证可禁用插件。

## 5. 数据模型

### Terrace Group

- 显式成员列表，作为成员归属的唯一来源，避免通过场景扫描或 Actor 标签猜归属；生成输出阶段增加组 ID。
- 目标 Landscape，后续使用软引用支持外部 Actor；首版同一组只服务一个 Landscape。
- 校验结果、更新状态、输出记录、默认风格（分阶段实现）。
- 未加载的 World Partition 成员需要报错/提示加载，不能当成不存在而删除输出。

### Terrace Plot

- 稳定 Plot ID：保存重开不变化，普通复制/粘贴产生新 ID，PIE 复制保留。
- 原生闭合 Spline、标高偏移、边界采样间距。
- 田埂宽度/高度、外围过渡宽度。
- 种植方向、行距、株距、边缘留白、随机种子。
- 后续增加作物预设、排水、共享边界、手工覆盖参数。

### 边界快照

将闭合样条离散为不重复首尾点的世界 XY 多边形，保存 Plot ID、世界标高、包围盒和参数。所有下游使用同一份快照，避免墙体与植被各自采样得到不同边界。采样必须保留样条段的角点并限制顶点数；生成前完整校验，失败不沿用旧快照。

## 6. 输入校验

M0：闭合、控制点数量、有限数值、正向缩放、水平放置、非零面积、重复/过短边、自交、最大采样数、参数范围、成员缺失/重复、重复 Plot ID。

M1 增加：目标 Landscape 有效且区域已加载、编辑层可用、田块越界、地形采样密度不足、Raster 预算、组内田块相交/重叠及共享边界冲突。

首版只接受单一简单多边形，允许凹形，不支持孔洞。闭合样条不代表一定是合法田块；自交、触碰自身、回折共线边均需拒绝。Spline 离散容差与最终几何精度有关，须在视口抽查急弯。

## 7. 地形整平（M1）

优先验证 Landscape Texture Patch：根据多边形栅格化目标高度和覆盖权重，内部为目标标高，外围按距离渐隐，写入工具拥有的 Patch / 程序化编辑层。不得将生成结果不断叠加到已修改高度上；每次从权威田块数据重建工具层的贡献。

M1 已有用户整体检验通过反馈，逐项结果未单独记录。若后续场景中 Patch 的覆盖/混合方式不能满足精确整平，再实现自定义 Brush 后端；不默认退回破坏性写基础 Heightmap。

高度转换需要明确世界 Z、Landscape 局部高度和高度纹理编码的区别，不能把世界厘米直接当 uint16 高度值。Raster 分辨率参考 Landscape 顶点间距和预算；不能承诺以低分辨率 Landscape 表达窄田埂或垂直墙。

多个田块的重叠与过渡先检测冲突，不依赖随机生成顺序决定最终高度。相邻田块使用统一的接缝策略，禁止不同标高的宽过渡带侵入对方田面。

阶段顺序：校验 → 快照 → Patch 更新 → Landscape 重组 → 碰撞/采样源就绪 → 结构 → PCG。使用可验证的完成条件，不能仅固定延时。异步任务携带生成版本号，过期完成回调不能覆盖新结果。

## 8. 田埂与挡土结构（M2）

- 沿相同边界生成断面，区分田埂顶、挡土侧面与墙脚。
- 高差由邻接田面/外围地面确定，禁止所有墙使用固定向下长度。
- 共用边只生成一次挡土结构。首版可要求不共享边、留合理间隔；自动邻接作为后续功能，不能声称 M0 已处理。
- 支持凹轮廓，处理急弯、自交、UV 拉伸和末端封口；不使用中心扇形假设所有田面凸。
- Landscape 提供主要田面碰撞；田埂、台阶提供额外网格碰撞。底层地形不能在可通行位置形成隐形凸起。
- 可选泥面要明确是视觉层还是承载碰撞层，避免双重近共面碰撞和 Z-fighting。
- 动态网格用于预览，定稿导出 Static Mesh；Nanite、LOD、距离场等按最终资产实际配置验证。

M2 首版采用 Runtime ProceduralMeshComponent 验证可保存、可行走的结构。内圈向田内占用埂宽，外侧土坡沿已整平的真实地形碰撞采样；不直接以网格遮盖仍存在的地形来伪造垂直挡土墙。底面和坡脚封口随实际地面埋入。偏移轮廓翻折时拒绝。该原型不等于 Static Mesh 烘焙、Nanite/LOD 或目标平台打包已完成。

地形输出记录已应用输入，结构生成前比较当前边界/标高/过渡与目标地形，检查更新状态并验证支撑处碰撞高度。改变地形时清理旧结构；单独改材质或埂宽/埂高可只更新结构。详细约束与未验证项见 M2 文档。

## 9. PCG 作物（M3）

输入快照 → 按田块方向生成规则行列 → 多边形裁剪 → 距边缘/沟渠/路径排除 → 小范围抖动与缺株 → 校验/投射到指定最终表面 → 实例化作物簇。

水田可直接按已确认田面标高生成点；需要射线时只允许指定承载面，不能命中旧山坡、作物或无关网格。随机性由 Plot ID、显式种子和稳定格点坐标组合，不依赖成员数组顺序。

`Create Surface From Spline` 输出 PCG 隐式空间表面，不生成可见田面网格；规则种植不要求依赖 Mesh Sampler。作物优先 ISM/HISM 等批量实例，远近密度、风动、阴影和裁剪在目标平台验证，不逐株 Spawn Actor。

## 10. 更新、撤回与持久化

- 分离校验、预览、地形结构更新、作物更新、清理及烘焙命令。
- 输出按组/田块/输出类别追踪，仅修改工具拥有的对象；重复生成替换旧结果。
- 修改地形前完成整组预检；错误时保留已有可用结果。
- Actor 创建、成员修改、控制点操作和资产引用修改放入 Undo 事务。GPU/异步地形变化的撤回需额外验证，不能仅凭 FScopedTransaction 宣称全部可撤回。
- 删除 Plot、删除组、清理输出、清除 Patch 贡献分别定义；不能误删手摆内容或其他组的地形贡献。
- 地形分析保留独立原始来源，后续自动等高线不读自身整平后的结果反复推导。

## 12. 测试策略

二维几何算法使用 UE Automation Tests，覆盖凹多边形、边界命中、退化边、自交/共线回折、大世界坐标与边界距离。对地形、序列化、事务和可行走性使用实际编辑器场景验证，数学测试不替代地形小样。

构建分别验证 Editor 与 Runtime 依赖。编辑器正在运行时不强制结束进程、不覆盖已加载模块；新 UCLASS/新模块需要重启编辑器后检查。按用户最新要求，后续编译和 UE 内测试由用户执行，提供步骤和预期结果；源码检查不等于编译通过。测试报告区分源码检查、编译、自动化测试和人工验收，未执行项明确保留。
