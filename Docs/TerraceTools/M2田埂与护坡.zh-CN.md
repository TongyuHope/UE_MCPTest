# M2 首版：田埂与土质护坡

0.4.0 流程更新：用户反馈本页方案可以生成田埂护坡，现优先改用 [PCG 沿线田埂](PCG田埂接入.zh-CN.md)。本页保留旧过程网格的说明；生成按钮已移至“网格实验”，主栏可清理旧网格。地形土埂暂未实现。

日期：2026-10-21。版本：0.3.1。M0/M1 已获用户整体检验通过反馈；0.3.0 用户反馈已看到台地，但生成结构时触发支撑高度报错。**本轮修复源码未编译、未运行自动化或 UE 测试，仍由用户执行**。

## 两个按钮分别做什么

“更新地形”把 Landscape 改成指定标高的台地，提供田内主要行走面。“更新田埂/护坡”读取该 Landscape 的实际碰撞，在 Plot 边界内侧生成凸起田埂，并向外生成贴合地面的土质护坡。它没有单独需要摆放的护坡 Actor 输入；选择 Group，按钮会处理其 Plots 列表中的田块。

使用顺序是：在 Plot 设置宽高和材质 → 选择所属 Group → 更新地形 → 等待地形和碰撞更新 → 更新田埂/护坡 → 出现 TerraceStructures 输出 Actor。默认没有指定材质时显示引擎默认材质。

## 0.3.1 支撑高度修复

0.3.0 从 Plot 边界立即衰减遮罩，但同时要求边界内外两条田埂支撑线高度接近田面。当边界未对齐 Landscape 网格，遮罩双线性过滤和地形三角形插值可能让边缘提前进入坡面。即使台地已经可见，也可能触发“支撑处地形碰撞未达到田面标高”的检查。这是实现中需要处理的精度问题，用户此前的按钮顺序正确；仅凭旧提示不能确认具体场景是否也存在碰撞更新延迟或其他编辑层覆盖。

0.3.1 在边界外自动保留平坦支撑余量，然后再开始 Transition Width 衰减，保持田埂原位置及原有高度检查。余量 = Landscape XY 网格对角线 + 遮罩采样对角线 + 1 cm；例如 Landscape XY Scale 都为 100、Terrain Raster Spacing=100 时约为 283.84 cm。**台地占地会扩大，相邻田块间距和地形边界余量也要增加。** 这是当前原型对精度的保守处理，尚未实现紧邻田块的共享边方案。

护坡有效宽度同步改为“支撑余量 + Transition Width”。从 0.3.0 升级后必须重新点击一次“更新地形”；旧输出会明确拒绝生成结构，不会沿用未加余量的台地。

若仍失败，新提示分别报告“支撑高度不匹配”和“地形盖住埂顶”，并给出田块名称、内/外沿、世界 XY、实际碰撞高度、目标标高及差值。先确认地形完成、两个 Collision Mip 为 0，再检查工具 Patch 层上方的其他编辑层；提供 Output Log 中该条完整提示，继续定位。不要通过调大 Ground Height Tolerance 绕过尚未更新的碰撞。

## 当前交付与范围

沿闭合田块生成田埂平顶、朝向田内的立面、贴合外围地形的土质护坡，以及埋入地下的底面和坡脚封口。支持独立田埂/护坡材质、厘米尺度 UV、结构碰撞、整组替换和单独清理。

这是 M2 的第一批可行走结构，**还没有实现垂直石墙、台阶、共享田边、网格资产烘焙或作物**。沿用 M1 的普通非 World Partition 小样限制，不支持孔洞。结构偏移造成自交、窄部塌陷或尖角超过限制时明确拒绝，不强行生成翻面。

M1 原本保留了地形渐变坡，本轮外侧护坡沿该坡面采样生成；不会将底层坡面切成悬崖。要做高而垂直的挡土墙，后续需联合调整地形剖面，避免墙后地形露出或形成隐形碰撞。

## 升级与操作

1. 保存工作，关闭 UE，完整编译并重启。插件新增 ProceduralMeshComponent 依赖和 Runtime 结构 Actor；不依赖本轮 Live Coding 来验收新类型。
2. 在普通测试关卡选中 Landscape，将 **Collision Mip Level** 和 **Simple Collision Mip Level** 都设为 0，并等待更新。
3. 在 Plot 中配置 `Bund Width`、`Bund Height`，可指定 `Bund Material` 和 `Bank Material`。首次行走样例建议宽度 100 cm、高度 30 cm；高度超过角色 Max Step Height 时，不保证能直接跨上田埂。
4. 选中 Group，使用 **更新地形**。从 0.2.0 / 0.3.0 升级的已有田块也必须至少更新一次，以应用当前版本的平坦支撑余量并记录输入快照。
5. 等待地形重组和碰撞更新后，点击 **更新田埂/护坡 / Update Structures**。
6. 出现 `TerraceStructures` 输出 Actor 后，检查转角、侧面和坡脚，运行角色行走验收。
7. 只改埂宽、埂高、材质或结构设置时，可直接再次更新结构。改田块位置、边界、标高、过渡宽度或地形 Raster Spacing 时，先更新地形，再更新结构。
8. **清理结构 / Clear Structures** 仅删除本组结构；保留 Landscape Patch。**更新地形**或**移除地形贡献**会清理旧结构，防止旧网格与新地形不一致，之后需要再次生成结构。
9. 保存关卡及相关地形包，重开并检查显示与碰撞。

“校验边界”仍仅校验田块轮廓，不能代替结构生成预检。更新结构失败时保留旧结构，并显示原因；旧结构代表上一次成功结果，不会自动跟随新编辑数据。

## 生成规则

Plot 边界为田埂外沿，田埂向田内占用 `Bund Width`；田埂顶标高为田面标高 + `Bund Height` + `Surface Lift`。作物后续要为该占用范围留白。

启用护坡时，从边界向外延伸到“自动支撑余量 + `Transition Width`”作为坡脚。其间在目标 Landscape 的 Complex 碰撞高度场采样，逐步将埂高及表面抬高量衰减到 0。下坡侧得到土质护坡；上坡侧随原有挖方坡面连接，不强制给每一边创建等高的挡土墙。

关闭 Generate Bank 时，只生成田埂实体及其外侧立面。不会产生单独田面，田内继续使用 Landscape 承载。

内外轮廓使用对应顶点，先去除同一直线上的冗余采样、偏移角点，再对成对轮廓补点，避免“埂宽大于角点附近采样间距”时内圈回折。偏移采用有上限的斜接方式；宽度不适配轮廓时应修改田块，而不是放宽自交检查。

## 参数

| 所在位置 | 参数 | 默认值 / 行为 |
| --- | --- | --- |
| Plot | Bund Width / Height | 60 / 30 cm；本轮开始实际参与结构生成；结构生成至少需要 1 cm |
| Plot | Bund Material | 田埂顶材质；留空使用引擎默认材质 |
| Plot | Bank Material | 护坡、内侧面及埋底材质；留空时回退到 Bund Material |
| Plot | Transition Width | 默认 150 cm；在自动平坦支撑余量之外开始衰减；护坡有效宽度为两者之和；改变后先更新地形 |
| Group | Structure Sample Spacing | 50 cm，最小 10 cm；控制结构轮廓与横向护坡细分 |
| Group | Generate Bank | 默认开启；关闭时仅生成田埂 |
| Group | Embed Depth | 10 cm，至少 1 cm；底部相对采样地面向下埋入 |
| Group | Surface Lift | 2 cm，至少 0.1 cm；田埂顶部及护坡内段的额外抬高，向坡脚衰减 |
| Group | Ground Height Tolerance | 10 cm，可设 0.1～20 cm；田埂支撑位置允许的碰撞高度误差；不要用大容差掩盖未更新地形 |
| Group | UV Tile Size | 100 cm；沿周长和断面方向平铺，可用世界投影材质减少接缝 |
| Group | Create Structure Collision | 默认开启；关闭后保留可见结构，但不提供结构自身碰撞 |

`Sample Spacing`（Plot 轮廓）、`Terrain Raster Spacing`（地形遮罩）和 `Structure Sample Spacing`（结构细分）是三项不同设置。

若坡面局部露出或坡脚贴合不足，应先检查地形碰撞是否最新、网格采样密度及材质位移，再调整 Surface Lift。离散采样不能保证连续坡面所有位置完全一致，需在目标景别验收；增加结构密度不会增加 Landscape 分辨率。

## 更新检查与生命周期

- M1 输出现在保存已应用的 Plot ID、边界、标高、过渡宽度、Raster Spacing、平坦支撑余量、Landscape Transform 和 Patch Transform。
- M2 比较输入是否匹配，检查 Patch 是否启用、目标层是否可见/解锁且 Alpha=1，并检查 `Landscape::IsUpToDate()`。
- 再实际采样田埂内外支撑处的高度，误差超限或埂顶被地形覆盖时拒绝。
- 这些检查不等于引擎所有派生任务均完成，实际行走与保存仍需验收；其他编辑层或手动修改 Patch 也可能改变结果。
- 新网格和材质预检全部成功后才替换旧输出。单个田块最多 65,536 三角形；整组最多 131,072；单圈最多 512 点，护坡横向最多 16 段，并限制成对轮廓检查预算。
- 删除组会清理自己拥有的地形与结构；删除结构输出会清空组引用；普通复制 Group 清空输出引用，PIE 保留生成网格。
- 删除 Plot 后需修复成员列表，再更新地形和结构，不能只删除 Plot 就期望旧结构自动消失。
- 不手动移动、缩放、复制生成输出；通过源 Plot 和 Group 修改。

## 保存、运行时与后续烘焙

`TerraceStructures` 位于 Runtime 模块，不是 Editor-only Actor。每块田一个 UProceduralMeshComponent，保存网格段、材质、位置及碰撞设置。运行时不 Tick、不重新采样或生成。地形 Patch 输出仍是 Editor-only。

结构采用 Complex-as-Simple 三角形碰撞，适用于静态地面/角色查询，不用于模拟刚体。当前使用同步碰撞烹制，较大网格更新可能阻塞编辑器；有预算上限，后续再按实际性能需要优化。

ProceduralMeshComponent 是原型阶段选择，不提供本工具的 Nanite、自动 LOD 或 Static Mesh 烘焙流程。后续正式生产化再导出 Static Mesh 并验证目标平台 Cook。**PIE 中可见或可走不能代替打包验收。**
