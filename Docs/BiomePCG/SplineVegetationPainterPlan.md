# BiomePCG 多样条植被绘制工具规划

> 首版源码实现已添加，操作说明见同目录 `SplineVegetationPainterUsage.md`。
> 尚未运行编译或编辑器交互验证；以下保留为设计与验收依据。

## 1. 目标与分工

在关卡视口中点击放置一个带 PCG 组件的蓝图 Actor，随后按住鼠标左键在地表绘制样条。
**每次独立的左键按下、拖动、松开，都生成一条新的独立样条；这些样条归属于同一个 Actor。**
PCG 图读取该 Actor 的全部目标样条，在每条线上按距离生成植被。

| 工作项 | 负责人 |
| --- | --- |
| PCG 图、沿线采样、植被选择、间距和随机变化等生成规则 | 用户 |
| Actor 的 C++ 基类、蓝图 Actor 创建支持、样条组件及持久化 | Codex |
| 视口放置、连续绘制、多条线管理、撤销及刷新通知 | Codex |
| 编译、启动编辑器、场景效果验收 | 用户；后续可按需调整 |

规划阶段先落地文档；用户随后已授权开始实现。现已添加源码，编译及场景验证交由用户执行。
下面的类名、入口名、资产路径按首版实现对应，尚待用户编译后验证。

## 2. 确定的交互流程

### 2.1 新建 Actor

1. 在 BiomePCG 工具入口点击“绘制样条植被”。
2. 未指定已有目标 Actor 时，进入“放置 Actor”状态。
3. 鼠标移动时显示地表命中点和放置预览。
4. 单击鼠标左键，在有效命中位置创建并选中蓝图 Actor。
5. 放置点击的按下和松开由放置操作消费；**该次点击不创建样条**。
6. Actor 放置后工具保持开启，进入等待绘制状态。

### 2.2 绘制多条独立样条

1. 再次按下左键，在有效地表命中位置开始一条新样条。
2. 按住左键拖动，沿地表连续记录控制点并显示曲线预览。
3. 松开左键，提交本条样条并通知 PCG 更新。
4. 下一次按住左键，创建另一条样条，仍归属当前 Actor。
5. 不自动连接到上一条线，也不把多次笔画拼成一条样条。

支持选择已有工具 Actor 后重新进入绘制模式，向该 Actor 继续添加新线。
“新建 Actor”作为显式操作提供，避免每次笔画都产生新的 Actor。

### 2.3 操作约定

| 输入或按钮 | 行为 |
| --- | --- |
| 首次有效左键点击 | 放置 Actor，不画线 |
| 放置后左键按住拖动 | 每次开始一条新线 |
| 松开左键 | 完成本条线 |
| Esc，正在绘制 | 取消当前未提交笔画，保留此前完成的线 |
| Esc，未在绘制 | 退出工具，保留 Actor 和已提交样条 |
| Ctrl+Z / Ctrl+Y，未在绘制 | 撤销 / 重做放置、整条笔画或删除操作 |
| 删除选中线 | 删除当前选中的一条完整样条 |
| 刷新生成 | 手动通知目标 PCG 组件重新生成 |
| 完成 | 结束绘制并返回正常关卡编辑 |

普通左键绘制与 Alt+左键等视口导航组合区分处理，保留右键视角导航。
鼠标位于工具面板、其他窗口时不向关卡写入点。

## 3. Actor 与组件结构

拟定 C++ 基类：`ABiomeSplinePainterActor`。
拟定蓝图：`BP_BiomeSplinePainter`，默认路径 `/Game/PCG/BP_PCG/BP_BiomeSplinePainter`。

```text
BP_BiomeSplinePainter : ABiomeSplinePainterActor
├── SceneRoot
├── PCGComponent
├── PaintedSpline_001 : UBiomePaintedSplineComponent
├── PaintedSpline_002 : UBiomePaintedSplineComponent
└── PaintedSpline_003 …
```

- 一个 Actor 默认只有一个负责生成的 PCG 组件。
- 每条手绘线对应一个独立的 USplineComponent 派生组件。
- 样条组件统一标记 Component Tag：`BiomePaintedSpline`，便于 PCG 只读取目标线。
- 每条线拥有序列化的稳定 GUID；显示名称和列表顺序不作为唯一身份。
- 第一版默认开放样条，不自动闭合，不自动连接相邻笔画。
- 绘制时使用世界空间命中位置，存入 Actor 本地空间，使整体移动、旋转时保持相对布局。
- PCG Graph 通过 PCG 组件的 Graph 属性由用户指定，允许蓝图默认值或实例覆盖。

### 蓝图资产的创建方式

工具提供创建或选用蓝图 Actor 类的支持，默认使用上述路径。
首次需要时通过编辑器资产 API 创建继承自 C++ 基类的蓝图；路径已有兼容资产时直接复用。
已有不兼容资产时报告路径冲突，允许选择另一位置，不覆盖资产。
不创建、不覆盖、不修改用户的 PCG 图。

## 4. 与用户 PCG 图的接口约定

### 输入

- 输入对象：当前 `BP_BiomeSplinePainter` 实例上的目标 Spline 组件。
- 建议以 `Get Spline Data` / 解析 Actor 组件的方式读取 Self，按需使用 Component Tag 过滤。
- 必须处理全部目标组件，避免只取第一个 Spline。
- 每条线保持独立的数据身份，不先合并控制点；采样距离在每条线内部计算。
- 不把 PCG 生成的组件再作为手绘输入收集，避免反馈循环。

### 用户负责的生成逻辑

```text
获取 Self 上的全部目标 Spline
    → Spline Sampler，按 Distance 采样
    → 植被预设 / 随机变换 / 地表投影 / 过滤
    → 用户的植被生成节点
```

工具不预设图中参数名称，也不强制注入间距、密度或 Mesh 列表。
第一版通过 PCG 图现有参数面板配置生成规则。
如需工具面板与 Graph 参数联动，再约定参数名、类型和默认值。

### 更新通知

- 提交、删除、撤销和重做样条后，使 PCG 输入失效并按设置触发生成。
- 无 Graph 时仍允许绘制和保存样条，只显示“未指定 PCG 图”的状态。
- 正在生成时合并重复刷新请求，避免多次提交互相堆积任务。
- 为用户保留“手动刷新”入口；工具不依赖强制即时生成才能提交笔画。

## 5. 视口绘制与地表投射

采用独立的 BiomePCG 编辑器交互工具，处理鼠标射线、绘制状态和事务。
原生 PCG Draw Spline 的绘制、射线过滤行为可作为参考，但本工具明确实现“放置一次、多次笔画、多条独立组件”的交互约定。
不直接依赖引擎 Private 目录中的绘制工具类。

### 碰撞和命中规则

- 使用鼠标视口射线拾取地表，默认支持 Landscape 和具有碰撞的 StaticMesh。
- 允许配置碰撞通道与目标范围。
- 排除本工具 Actor 的生成组件、PCG 生成的植被等，避免下一笔画到树冠上。
- 无有效命中时显示不可绘制提示，不向原点或任意平面自动补点。
- 笔画中断命中时不插入无效点；如重新命中点与前一点间距过大，则结束当前有效笔画，并等待左键松开后才能新建下一条，避免跨空洞自动连线。
- 工具失去输入捕获、目标 Actor 被删除或退出关卡时，取消当前未提交笔画并清理临时预览。

### 点数与曲线质量

- 按世界距离阈值追加控制点，不能按每帧无条件追加。
- 绘制点间距与植被采样间距是两个独立参数，互不绑定。
- 第一版提供“平滑曲线 / 折线”选项；平滑采用自动切线，折线用于要求紧贴地形的路径。
- 平滑曲线可能在控制点之间穿过地表；最终植被是否精确贴地，由用户 PCG 图中的地表投影逻辑负责。
- 松开时尽量保留有效笔画终点；有效控制点不足两个或总长度低于阈值时，丢弃本条线。
- 后续可以增加曲线简化、重采样和表面拟合，但不作为首版前置条件。

## 6. 保存、撤销与后续编辑

- 样条是关卡 Actor 上可序列化的实例组件，不是临时绘制对象。
- 正确设置组件所有者、实例组件关系、注册及事务标记，提交后标记对应关卡/Actor 包为待保存。
- 不在 Construction Script 中清空并重建全部手绘组件。
- Actor 放置为一个事务，每条完整笔画为一个事务，删除一条线为一个事务。
- 取消笔画不遗留空组件，不撤销之前已完成的笔画。
- 选中线可高亮显示，后续使用常规 Spline 控制点编辑；控制点修改后同样需要通知 PCG 刷新。
- 撤销 / 重做后重建工具中的组件列表缓存，并通知 PCG；缓存不是持久化数据源。
- 组件持久化方案需覆盖关卡重开、Actor 复制和蓝图重新编译，必要时实现组件实例数据恢复。

## 7. 面板与刷新策略

首版面板提供以下内容：

| 区域 | 内容 |
| --- | --- |
| 目标 | 当前 Actor、使用已有目标、新建目标、蓝图类选择 |
| 绘制 | 地表拾取设置、控制点最小间距、平滑或折线 |
| 样条列表 | 名称、长度、点数、选中高亮、删除选中线 |
| PCG | Graph 状态、提交后自动刷新开关、手动刷新 |
| 状态 | 等待放置、等待绘制、正在绘制、等待生成 |

首版默认：拖动时只更新曲线预览，松开提交后再刷新 PCG。
后续可提供节流的实时植被预览；不得让每个鼠标移动事件都启动一次完整生成。
不把 Foliage 烘焙绑定到绘制操作，绘制期间保留可编辑的 PCG 结果。

## 8. 插件模块边界

| 模块 | 拟新增职责 |
| --- | --- |
| BiomePCGRuntime | Actor 基类、样条组件、可序列化属性、PCG 组件引用 |
| BiomePCGEditor | 绘制 Interactive Tool、视口行为、事务、编辑器事件、蓝图资产创建 |
| BiomePCG | 现有 TA Tools 入口，增加启动绘制工具的菜单或按钮 |

根据实际依赖补充 InteractiveToolsFramework 等模块，编辑器输入、资产创建和 UnrealEd 类型保持在 Editor 模块内。
Actor 和组件的反射类型保持可在普通 Actor 蓝图中使用，避免再次出现运行时蓝图引用 Editor 模块类型的问题。
用户编写的 PCG 图不应依赖绘制工具处于开启状态，工具关闭后仍能正常读取已保存样条。

## 9. 实施顺序

1. 构建结束后实现 Actor 基类、样条组件、实例组件持久化及 PCG Graph 指定入口。
2. 实现“单击放置”与“下一次左键按住开始画线”的输入状态机。
3. 实现每次笔画创建新组件、地表投射、控制点距离阈值及松开提交。
4. 补齐取消、整笔撤销 / 重做、删线、已有 Actor 继续添加等行为。
5. 接入样条修改后的 PCG 失效通知、刷新合并和面板状态。
6. 用户编译，指定自己的 PCG 图并进行场景验收，根据实际反馈调整交互。

实现过程中不自动启动构建、不自动关闭编辑器；本次以新增源码为主，未移动现有模块或反射类型。
需要观察效果的工作留到用户当前构建结束、工具代码编译完成之后进行。

## 10. 首版验收标准

- 单击放置只创建一个目标 Actor，不额外产生一条空线。
- 连续三次左键笔画产生同一 Actor 下三条独立 Spline，不存在笔画间的自动连线。
- 短点击、无命中和取消操作不留下空样条。
- 选择已有工具 Actor 可继续添加第四条线，不新建其他 Actor。
- 撤销一次可以移除一整条最近笔画；重做可以恢复该笔画。
- 拖动时不连续触发完整 PCG 生成；提交后按设置刷新。
- 用户 PCG 图能读取所有目标线，并在每条线上独立按距离采样。
- 没有指定 Graph 时仍可保存绘制结果，稍后指定 Graph 再生成。
- 保存并重开关卡后样条保留；复制 Actor、编译蓝图后手绘数据不丢失。
- 退出绘制工具后，常规选择、相机导航和原生样条控制点编辑正常。
